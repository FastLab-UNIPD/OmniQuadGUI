PROJECT
-------
OmniQuadGUI: a Python 3 / GTK 3 desktop app, UBUNTU ONLY (22.04 / 24.04),
with an embedded VTE terminal that connects over SSH to a drone's
onboard computer (Radxa Rock 5B, ROS 2, Docker). It starts/stops the
px4_fastlio_bridge container and inspects ROS topics. It does NOT
control flight, but it may be used to READ data during a flight (topics,
echo, diagnostics, status); README warns not to Stop the container or
Shut down while flying.

User: mechanical engineering student with basic Python. Code must stay
simple, readable, heavily commented, no advanced patterns. Error
messages in plain English. Do not re-add Windows / platform switches
unless the user asks.

Folder: /home/pil8/Desktop/OmniQuad_Stuff/OmniQuadGUI (portable: can be
copied to any PC / user / location).

HOW TO RUN / TEST
-----------------
Run:   ./launch.sh   or   python3 main.py   (demo: python3 main.py --demo,
       or log in with demo / demo).
Test:  the user's login shell sources ROS Jazzy, so use a clean env:
       env -i DISPLAY=:0 HOME=$HOME PATH=/usr/bin:/bin:/usr/sbin \
         XAUTHORITY=$XAUTHORITY XDG_RUNTIME_DIR=$XDG_RUNTIME_DIR \
         DBUS_SESSION_BUS_ADDRESS=$DBUS_SESSION_BUS_ADDRESS \
         python3 -m unittest discover -s tests
       (21 run, 1 skipped: the loopback SSH test needs the CI fixture.
       Add -W error::ResourceWarning to catch unclosed pipes.)
Test pattern: demo login, or patch run_ssh_background; drive the main
loop with GLib.MainContext.default().iteration(False) until a condition
holds; stub dialogs (Gtk.FileChooserDialog, show_loud_warning).

BEHAVIOUR / ARCHITECTURE
------------------------
- Connect: background `sshpass -e ssh ... echo ok` check (password via
  SSHPASS env only), plain-English errors (explain_ssh_error). Then the
  real session in the terminal: sshpass -e ssh -o ControlMaster=yes
  -o ControlPath=<mkdtemp omniquad-*/ssh-ctl> -o
  StrictHostKeyChecking=accept-new. Successful user/ip are remembered in
  ~/.local/state/OmniQuadGUI/connection.json.
- Background commands: run_ssh_background() -> ssh -o ControlPath=...
  -o BatchMode=yes user@ip "<cmd>" in a thread; result + output go to the
  log; GUI updates only via GLib.idle_add. Demo mode answers via
  demo_answer() with a small simulated state (demo_container_running).
- Connection status: check_connection() every STATUS_CHECK_SECONDS=5
  once the master socket exists: ssh ... true (timeout 6 s, NOT logged,
  never typed into the terminal) + describe_network(ip) (`ip route get`,
  `nmcli -g GENERAL.TYPE,GENERAL.CONNECTION device show <dev>`, every
  step optional). Stops when the session ends. No ServerAlive options
  were added to the ssh session itself.
- Bridge state: self.container_running True/False/None is the single
  source of truth. set_container_state() -> update_bridge_widgets() +
  update_shell_button_state(); demo_run() also updates the widgets.
  Checked automatically after connecting and after start/stop
  (CONTAINER_LIST = docker ps --format "{{.Names}}|{{.Status}}", no sudo;
  permission-denied gets the usermod explanation).
- Start: commands.json start_container command (./nuc_helper.sh run ...),
  then re-check. Stop = SAFE sequence: docker ps check -> leave the
  container shell first if inside -> ./nuc_helper.sh stoprm -> verify.
- Shutdown (two clicks): leave shell + stoprm + verify; SAFETY-CRITICAL:
  abort with a loud dialog if the check failed or the container still
  runs. dry_run (default true) only logs. Real: sudo -S -p '' shutdown
  now with the password through ssh STDIN.
- Container shell: "Enter" types docker exec -it px4_fastlio_bridge bash
  and sets inside_container_shell; ROS buttons work only while it is
  set. "Leave" = Ctrl+C, 0.5 s, `exit`. Enter needs container_running
  True.
- Topics: on_list_topics() runs IN THE BACKGROUND
  topic_list_command() = docker exec -- px4_fastlio_bridge bash -ic
  'ros2 topic list' (interactive bash loads the ROS setup; introduced by
  PR #1). topic_names() keeps unique lines starting with "/". Filter is
  local; selection enables "Echo selected topic".
- Echo commands open their OWN terminal window each (open_echo_window:
  ssh over the control socket -> docker exec -it ... bash -> 1.5 s ->
  the echo command); several can run at once; closing stops it. hz
  commands type into the main terminal.
- LOCAL FOXGLOVE BRIDGE (local_bridge.py + build_local_bridge_panel):
  main() creates ONE LocalBridge (create_local_bridge) before the
  login window, starts it if commands.json local_bridge.autostart, passes
  it to every OmniQuadApp (survives Reconnect), and stops it in main()'s
  `finally` with stop(wait=True). Started as
  bash -ic 'command -v ros2 || source <ros_setup>; exec <command>'
  (bash -i reads ~/.bashrc = the user's ROS env + ROS_DOMAIN_ID; the
  app's own env stays ROS-free), stdin DEVNULL, stdout+stderr piped,
  start_new_session=True (own process group). Stop: SIGINT to the
  group, then SIGTERM, then SIGKILL after STOP_GRACE_SECONDS=5 each,
  escalating while ANY group member lives (group_alive), not only the
  main process. A reader thread forwards lines via GLib.idle_add to
  on_output (-> log, prefix "[foxglove]"), keeps the last 300 in
  recent_lines (replayed when a main window opens), and reports the end
  (on_state_changed). Plain-English tips for: package not found, ros2
  not found, address already in use. Before every start(),
  stop_leftovers() scans /proc for this user's copies NOT started by us
  (is_same_program: argv contains the command, first word compared by
  basename, or argv[0] basename == name; group leaders are signalled as
  a whole group) and stops them with LEFTOVER_STOP_STEPS (SIGINT 3 s,
  SIGTERM 2 s, SIGKILL 1 s; zombies count as gone), then starts fresh.
  main() turns SIGINT, SIGTERM and SIGHUP into a normal window close,
  so `finally` still stops the bridge. Refresh button on the card:
  on_check_local_bridge runs LocalBridge.check() in a thread (read-only:
  own pid, find_leftovers(), port_listeners(port) from /proc/net/tcp(6)
  + /proc/*/fd, so it never connects to the bridge); describe_check()
  turns it into (state, label text, log line). BridgeStatus.set_state
  takes an optional text ("RUNNING, NOT STARTED HERE", grey). If the
  bridge started/ended during the check, the live state wins. The
  card (BridgeStatus, Start/Stop Gtk.Stack) is NOT in self.controls, so it
  stays usable while drone controls are disabled / disconnected.
  self.controls is a WidgetGroup(host_card, bottom row) - only the
  drone sections. Verified on this PC: listening on :8765 after ~1.2 s,
  clean stop in ~0.8 s, no leftover processes.
- Log area capped at MAX_LOG_LINES 5000 / MAX_LOG_CHARS 512000.
- Every message the app prints into a VTE terminal goes through
  feed_text() ("\n" -> "\r\n", no "staircase" text).
- main() wraps everything: unexpected exceptions show a dialog with the
  traceback (no console when started from the launcher).

SAFETY RULES (never break)
--------------------------
- Passwords: SSHPASS env var only (sshpass -e); never on a command line,
  in the log or on disk; sudo password only via ssh stdin.
- Never send a bare `exit` unless inside_container_shell is True (it
  would close the whole ssh session).
- Shutdown only after a VERIFIED stopped container; dry_run defaults on.
- Never start the bridge while its state is unknown.

LESSONS (do not regress)
------------------------
- Clean environment: with ROS Jazzy sourced, LD_LIBRARY_PATH made GTK/VTE
  load wrong libraries (window visible but frozen). main.py re-execs
  itself (os.execve) with a whitelist (ENV_VARS_TO_KEEP; PATH without
  /opt/ros, conda, venv entries); marker OMNIQUAD_CLEAN_ENV=1 prevents a
  restart loop; clean_own_environment() is only the fallback.
- No cairo: python3-gi-cairo is missing, so no Gdk.cairo_* and no
  DrawingArea "draw" handlers. Images: Gtk.Image.new_from_gicon(pixbuf)
  + set_pixel_size (sharp on HiDPI). RotorSpinner is a flip book:
  rotor_frame_svg() makes 24 frames per 120 degrees (three blades) once
  (FRAME_CACHE), a tick callback swaps them; Gtk.Spinner fallback if SVG
  cannot be drawn. ui_theme.py must call gi.require_version for Gtk,
  Gdk and GdkPixbuf itself (imported alone it would get GTK 4's Gdk).
- Window sizing: with a header bar, an unrealized window reports a tiny
  size and hidden widgets report 0. So open_main_window does
  header.show_all() + layout.show_all(), then hide_until_needed() (the
  Confirm-shutdown pair and the topics rotor), then
  fit_window_to_content(window, 1360, 720, parts=[header, layout]) (sum
  of natural sizes, clamped to the monitor work area), then
  window.show() - NOT show_all(), which re-revealed the hidden widgets
  at map time and opened the window too wide.
- Paned: pane.pack1(left_pane, True, False) (terminal side takes extra
  width, never clipped) and pane.pack2(sidebar, False, False) with
  sidebar policy NEVER horizontally (buttons never hidden); the divider
  is set to window width - sidebar natural width.
- Login window: Gtk.Overlay measures only its main child (the logo); a
  Gtk.SizeGroup (BOTH) between logo and form keeps the form unclipped.
- no_show_all widgets ignore show_all() even on themselves.
- Gtk.Stack.set_visible_child_name() is ignored while that child is still
  hidden: show the stack's children (button.show_all()) BEFORE adding
  them, or a toggle built for the "running" state shows "Start".
- Never read export data back out of row widgets (an icon in a row once
  broke the old container CSV export).
- VTE spawn_async argument order on this Ubuntu: (Vte.PtyFlags.DEFAULT,
  None, argv, envv, GLib.SpawnFlags.SEARCH_PATH, None, None, -1, None,
  callback). Wrong order = invisible TypeError when started from a
  launcher.
- VTE 0.68 (Ubuntu 22.04) has no get_text_format(); anything reading the
  terminal screen must fall back to get_text().
- Portable .desktop launcher: the Exec line must pass
  desktop-file-validate, which rejects single quotes and field codes
  inside quotes. Pass %k as a separate argument instead:
  Exec=bash -c "exec \\"\\$(dirname \\"\\$1\\")/launch.sh\\"" OmniQuadGUI %k
  (works from Files and from `gio launch`). Icon=omniquadgui.
- A copy of the launcher OUTSIDE the folder (e.g. on the Desktop) can't
  use %k; it finds the app via
  "$(xdg-user-dir DESKTOP)/OmniQuad_Stuff/OmniQuadGUI/launch.sh".

OPEN ITEMS
----------
- Topic listing via `bash -ic` (PR #1) should be confirmed on the real
  drone; the older non-interactive docker exec variant had failed there
  because it had no ROS environment.
- If the user types `exit` by hand inside the container, the app's flag
  stays True until Leave/Stop/Shutdown (README: always use Leave).
- The empty space in the top row of the right panel (after the Foxglove
  card) is reserved for future controls.
- foxglove_bridge listens on 0.0.0.0:8765 (all interfaces) by default;
  pass address:=127.0.0.1 in the command if it must be local-only.
- If the app is killed hard (SIGKILL / crash of Python itself), the
  bridge keeps running (own process group) until the next app start,
  which restarts it (stop_leftovers). Verified on this PC: a stuck
  bridge was replaced at start, and `kill <app pid>` left nothing.
