PROJECT
-------
OmniQuadGUI: a Python 3 / GTK 3 desktop app for Ubuntu with an embedded
VTE terminal that connects over SSH to a drone's onboard computer
(Radxa Rock 5B, ROS 2, Docker). It manages containers and inspects ROS
topics. It does NOT control flight. User is a mechanical engineering
student with basic Python: code must stay simple, readable, heavily
commented, no advanced patterns. Plain-English error messages.

Folder: /home/pil8/Desktop/OmniQuad_Stuff/OmniQuadGUI (portable: copyable
to any PC / user / location).

Launcher: OmniQuadGUI.desktop INSIDE the project folder, now PORTABLE
(%k = the desktop file's own location -> runs launch.sh next to it;
no user name, no absolute path anywhere). launch.sh cds to its own
folder, installs omniquadgui.png once into
~/.local/share/icons/hicolor/256x256/apps (so Icon=omniquadgui works
without admin rights), then execs python3 main.py. Use by double-click
in Files (Allow Launching once). The desktop entry uses a
desktop-file-validate-compliant, shell-free path handoff to launch.sh.
`gio launch` from a terminal leaves %k EMPTY (stdin case) and would fail;
use Files/GNOME or run `./launch.sh` from a terminal instead.

BUGFIX PASS (Nov 2026, after user reports)
------------------------------------------
1) FROZEN GUI when started from a terminal (window appeared but nothing
   was clickable; desktop icon was fine): the user shell sources ROS
   Jazzy, which sets a long LD_LIBRARY_PATH full of /opt/ros/...
   vendor libraries. Removing ROS_* vars + PYTHONPATH was NOT enough --
   LD_LIBRARY_PATH made GTK/VTE load incompatible library copies.
   FIX: main.py now RESTARTS ITSELF with os.execve in a whitelisted
   clean environment (ENV_VARS_TO_KEEP: DISPLAY, XAUTHORITY,
   WAYLAND_DISPLAY, XDG_*, DBUS_SESSION_BUS_ADDRESS, HOME, USER,
   LANG/LC_*, TERM...; PATH kept but /opt/ros|conda|envs|venv entries
   removed). Marker env var OMNIQUAD_CLEAN_ENV=1 prevents an infinite
   restart loop; clean_own_environment() stays as fallback if execve
   fails. The app now behaves like a desktop-icon start from EVERY
   launcher (launch.sh included).
2) Ubuntu 22.04: topic list stayed EMPTY (spinner forever). Cause:
   Vte.Terminal.get_text_format() only exists since VTE 0.76 (Ubuntu
   24.04 has it; 22.04 ships 0.68 and does NOT). The poll callback
   raised AttributeError every 0.5 s and silently died. FIX:
   _read_terminal_screen() now tries get_text_format -> get_text() ->
   get_text(None, None) -> get_text_range(visible screen). On old VTE
   get_text() returns the WHOLE scrollback, so topics scrolled off
   screen are captured too.
3) Hardening: the topic marker is now typed as  echo "MARKER"  (quoted)
   so a wrapped fragment of the echoed command line can never exactly
   equal the printed marker line (narrow windows wrap the typed
   command over several rows; the poll matches whole stripped lines).
4) NOTE: the copy of the old absolute-path Desktop shortcut the user
   pasted into the project folder had OVERWRITTEN the portable
   OmniQuadGUI.desktop. Restored to the portable version
   (Exec=bash -c 'cd "$(dirname "%k")" && exec ./launch.sh',
   Icon=omniquadgui); verified it parses via Gio.DesktopAppInfo
   (new_from_filename -- do NOT run gio launch, %k stays empty).

STARTUP WINDOW SIZE FIX (Nov 2026)
----------------------------------
Windows had to be resized by hand before all buttons were visible.
- Main window: the right button sidebar (ScrolledWindow in the
  horizontal Paned) could shrink to ~170 px, hiding most buttons. Now:
  sidebar policy NEVER horizontal (so it asks for the full button
  width), pack2(sidebar, resize=False, shrink=False), natural width AND
  height propagated, window size from fit_window_to_content() (content
  size, min 1200x720, clamped to the monitor work area), and the divider
  set so the sidebar gets exactly its natural width.
- Start window: Gtk.Overlay only measures its MAIN child (the logo), so
  the form on top was clipped. A Gtk.SizeGroup (BOTH) links logo and
  form so the window always fits the form, also with long errors.
  Do not remove that SizeGroup.

IMPORTANT TECHNICAL LESSONS (do not regress)
--------------------------------------------
- clean_own_environment() runs BEFORE the gi import: it removes ROS_*
  vars + AMENT_PREFIX_PATH and strips /opt/ros/* PYTHONPATH entries from
  the APP's own environment. With ROS Jazzy sourced in the user's shell
  the app was unreliable -- it only started properly from the desktop
  icon (clean env). Now the app behaves the same from every launcher.
  UPDATE (bugfix pass): the surgical cleanup was NOT enough (frozen GUI
  from a terminal -- see BUGFIX PASS item 1). The app now re-execs
  itself into a whitelisted clean env first; clean_own_environment()
  is only the fallback.
- Portable .desktop lesson: %k expands to the desktop file's own path
  ONLY when launched by a real launcher (GDesktopAppInfo from filename,
  like Files/desktop do). `gio launch` feeds the file via stdin and
  leaves %k EMPTY. The Exec field must still pass
  desktop-file-validate; shell quoting that happens to work in GNOME can
  be rejected by other launchers.
- VTE spawn_async on this Ubuntu:
  (pty_flags, working_dir, argv, envv, GLib.SpawnFlags.SEARCH_PATH,
   child_setup, child_setup_data, timeout, cancellable, callback)
  -> (Vte.PtyFlags.DEFAULT, None, argv, envv, SEARCH_PATH, None, None,
      -1, None, cb). Wrong order = invisible TypeError from .desktop.
- main() wraps app in try/except: unexpected exceptions show a
  Gtk.MessageDialog with traceback (hidden-console safety net).
- Test pattern: env -i DISPLAY=:0 HOME=... PATH=... python3; stub
  start_ssh_session; demo login OR monkeypatch run_ssh_background with
  canned queue (pop per call); test sequences SEQUENTIALLY; stub
  dialogs. User's login shell has ROS Jazzy env - clean env needed.
- Password rules: SSHPASS env var only (sshpass -e), never command
  line/logs/disk; sudo password via ssh stdin only; config.json never
  stores passwords. Demo creds are not security.
- Never send a bare `exit` unless inside_container_shell is True.
