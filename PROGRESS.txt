PROJECT
-------
OmniQuadGUI: a Python 3 / GTK 3 desktop app for Ubuntu with an embedded
VTE terminal that connects over SSH to a drone's onboard computer
(Radxa Rock 5B, ROS 2, Docker). It manages containers and inspects ROS
topics. It does NOT control flight. User is a mechanical engineering
student with basic Python: code must stay simple, readable, heavily
commented, no advanced patterns. Plain-English error messages.

- Close: ssh -O exit, temp dir removed. Start window closes when main
  opens (disconnect its Gtk.main_quit handler first).

Stage 2 (confirmed by user):
- Host buttons from commands.json: docker ps check (list in GUI,
  permission-denied explanation), start container, SAFE stop sequence
  (check -> leave shell if flag -> stoprm -> verify), two-step shutdown
  with SAFETY-CRITICAL verify: abort + loud dialog if container still
  running or check failed; dry_run prints instead of shutting down;
  real shutdown = sudo -S -p '' shutdown now with password via ssh
  stdin; afterwards buttons disabled, calm connection-lost message.
- Remote reads in background threads:
  ssh -o ControlPath=<socket> rock@<ip> "<command>"; GUI updates only
  via GLib.idle_add; every command+output appended to the log area.

Stage 3 (all 22 headless checks pass):
- Terminal buttons built from commands.json. ROS buttons DISABLED until
  "Enter PX4 bridge container" is used (types docker exec -it
  px4_fastlio_bridge bash, sets inside_container_shell=True); disabled
  again by Leave (Ctrl+C, 0.5 s, exit; only allowed while flag set) --
  leave_container_shell() now also calls update_shell_button_state(),
  so stop/shutdown sequences reset the buttons too.
- "Stop current command" sends Ctrl+C (b"\x03").
- "List available topics": types "ros2 topic list" INTO the terminal
  (ros2 only exists inside the container shell), waits 3 s, then reads
  the printed topics from the terminal screen
  (get_text_format(Vte.Format.TEXT), lines starting with "/", deduped)
  and fills the clickable SINGLE-selection Gtk.ListBox with its own
  spinner; clicking a row sets selected_topic. The old background
  "docker exec ... ros2 topic list" variant failed on the real drone
  (non-interactive shell has no ROS env) - do not bring it back.
- "Echo selected topic": types "ros2 topic echo <selection>".
- Fixed buttons type their commands.json command (odometry echo,
  --field pose.pose.position, covariances grep, rmem_max, IMU/LiDAR hz).
- Helpers: type_in_terminal(cmd) and send_ctrl_c() log "[terminal] $"
  and are demo-safe; find_terminal_command(action) reads commands.json.

IMPORTANT TECHNICAL LESSONS (do not regress)
--------------------------------------------
- VTE spawn_async on this Ubuntu:
  (pty_flags, working_dir, argv, envv, GLib.SpawnFlags.SEARCH_PATH,
   child_setup, child_setup_data, timeout, cancellable, callback)
  -> (Vte.PtyFlags.DEFAULT, None, argv, envv, SEARCH_PATH, None, None,
      -1, None, cb). Wrong order = invisible TypeError from .desktop.
- main() wraps app in try/except: unexpected exceptions show a
  Gtk.MessageDialog with traceback (hidden-console safety net).
- Test pattern: env -i DISPLAY=:0 HOME=... PATH=... python3; stub
  start_ssh_session; demo login OR monkeypatch run_ssh_background with
  canned queue (pop per call); test sequences SEQUENTIALLY; stub
  dialogs. User's login shell has ROS Jazzy env - clean env needed.
- Password rules: SSHPASS env var only (sshpass -e), never command
  line/logs/disk; sudo password via ssh stdin only; config.json never
  stores passwords. Demo creds are not security.
- Never send a bare `exit` unless inside_container_shell is True.
